## 1. 测试目的

验证系统在本地/内网部署形态下，能否完整、正确、安全地完成：

1. **非结构化脱敏**：TXT / DOCX / PDF / 扫描件 / 图片的识别、复核、脱敏、导出
2. **结构化脱敏**：CSV / XLSX / JSONL / SQLite 及 PG/MySQL 直连的字段策略与交付
3. **视觉要素脱敏**：公章、签字、人脸、证件、二维码、指纹等定位与遮盖
4. **DICOM 医疗影像匿名化**：导入 → 风险识别 → 复核 → 匿名化 → 导出回读
5. **批量与万级运营**：任务队列、审阅确认、异步分卷导出、断点续传
6. **安全合规与运维**：角色矩阵、审计、租户隔离、License/LDAP/API Key、备份恢复

并核对白皮书/交付清单中的**技术门槛**是否可被自动化资产复验。

## 3. 被测对象与技术要求

### 3.1 架构要点

- **本地优先**：OCR（PP-StructureV3 / 可选 PaddleOCR-VL）+ HaS Text NER + LocateAnything-3B 视觉特征 + OpenCV 印章补全，无外部推理 API 依赖
- **前后端**：React 前端（Node 24）+ FastAPI 后端（Python 3.11）
- **部署**：Docker（CPU API）/ GPU profile；生产双卡实测形态见 `deploy/`

### 3.2 关键技术门槛（验收标准）

| 类别 | 要求 | 来源 |
|---|---|---|
| 识别质量 | identity 召回 = **100%**；standard ≥ **85%** | `e2e/industry_recall.py`、白皮书 §2 |
| 吞吐 | 双卡优化后约 **≥29 文件/分**（文档记载峰值约 32.21） | 白皮书 §3、交付清单 |
| 规模 | 万级批量（实测 6720）；导出分卷 ≤2GB；库表十万行可导出 | 白皮书 §4 |
| 安全 | 五角色 + 对象级属主校验；审计可检索导出；租户隔离零泄漏 | 交付清单、SECURITY.md |
| 工程门禁 | CI：前端 build、ruff、pytest、Docker build | `.github/workflows/ci.yml` |

## 5. 测试策略与过程

### 5.1 分层闸门

```text
L0 静态/构建     → CI：tsc build、ruff、import app、Docker build
L1 单元/组件     → backend pytest（93 模块 / 582 用例）；frontend vitest
L2 黄金路径 E2E  → smoke / perm / golden_*（单文件、批量、库表、导出、改密）
L3 质量与规模    → industry_recall、benchmark_throughput、concurrent_users、longevity、EN locale
L4 DICOM 专项    → docs/dicom-validation.md + test_dicom_*
```

### 5.2 标准复跑流程

1. **准备**：安装依赖；配置 `.env` 与模型路径
2. **L0**：`ruff check app/` → `pytest tests -q` → `npm run build` → Docker build
3. **L1 E2E 冒烟**：`python e2e/smoke_routes.py` + `python e2e/perm_matrix.py`（或 `npm run e2e`）
4. **L2 黄金路径**：`golden_single` → `golden_batch` → `golden_structured` → `golden_export` → `golden_password`
5. **L3 质量门**：`python e2e/industry_recall.py legal|medical|finance|gov`（identity&lt;100% 或 standard&lt;85% 即失败）
6. **性能（可选 GPU）**：`backend/scripts/benchmark_throughput.py`
7. **归档**：失败截图写入 `e2e/.artifacts/`；召回记分卡 `{pack}_recall.md`

### 5.3 判定规则

- 断言失败 → 非 0 退出码，CI/门禁可直接接
- 成品页 PII 断言必须 scope 到 `playground-redacted-pane`
- Auth 限流 5 次/分钟：连跑遇 429 等待约 65s 后重试

### 5.4 复跑命令速查

```bash
# 后端全量
cd backend && python -m pytest tests -q

# E2E Tier1
cd e2e && python smoke_routes.py && python perm_matrix.py

# E2E Tier2
python golden_single.py && python golden_batch.py
python golden_structured.py && python golden_export.py

# 质量门（四行业）
python industry_recall.py legal
python industry_recall.py medical
python industry_recall.py finance
python industry_recall.py gov
```

## 9. 测试结论

1. **功能完备性**：单次处理、批量五步、库表处理、任务/结果、视觉脱敏、DICOM、导入与企业集成等主要功能均有对应自动化覆盖，与操作手册动线一致。
2. **技术要求达成**：identity 100%、standard ≥85% 质量门、万级批量与异步分卷、角色/审计/隔离、本地不出域等关键技术要求，在版本化语料与生产实测文档中均判定通过。
3. **可回归性**：质量与黄金路径以代码库脚本固化，具备客户环境复跑条件；后端 **582** 条用例可作为持续回归基线。
4. **总体结论**：在文档记载的生产验收基线上，**RedactionEverything v1.0.0 主要功能与相关技术要求测试通过，同意按已知边界交付/上线**。建议每次识别管线或权限相关变更后至少执行「CI pytest + Tier1/2 E2E + 受影响行业 `industry_recall`」，发版前补跑吞吐与并发脚本。
